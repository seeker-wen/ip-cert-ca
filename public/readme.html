背景与目的

在企业内部环境中，有时我们需要为没有域名的服务提供 HTTPS 加密连接。这通常是因为这些服务只在局域网内运行，或者出于成本和管理方面的考虑不需要注册公开域名。

为了满足这一需求，一个基于 B/S 架构的内部 HTTPS 证书签发系统诞生了。通过这个系统，我们可以轻松地为内部服务签发和管理 HTTPS 证书，确保数据传输的安全性。

工作原理

根证书

  • 定义：根证书是一张特殊的证书，用于信任其他证书。
  • 生成：系统会自动生成一个根证书，并允许用户下载安装。
  • 安装： 用户需要将根证书安装在他们的设备上（如电脑或移动设备）。

IP 证书

  • 申请：在系统中输入需要保护的服务的 IP 地址，系统会自动为该 IP 生成一张证书。
  • 签发：生成的证书由上述的根证书进行签名，证明其有效性。
  • 部署：将签发好的证书部署到服务器上，以启用 HTTPS。

如何使用

下载并安装根证书

  1. 访问我们的证书签发系统网站。
  2. 下载根证书文件。
  3. 直接双击该文件来启动安装过程。会打开一个证书导入向导，选择将证书放置到 受信任的根证书颁发机构 或受信任的发布者存储

自助申请 IP 证书

  1. 输入需要保护的服务的 IP 地址。
  2. 系统会自动生成一张 IP 证书供下载。

配置 Nginx 服务器

步骤 1: 备份现有配置

在开始前，请先备份现有的 Nginx 配置文件。

通常配置文件位于 /etc/nginx/nginx.conf 或 /etc/nginx/sites-available/ 中。

步骤 2: 编辑配置文件

找到需要启用 HTTPS 的服务的配置部分。

      
        server {
            listen 443 ssl;
            server_name <IP地址>;
            
            ssl_certificate /path/to/cert.pem;  
            ssl_certificate_key /path/to/key.pem;  
            
            
            
            location / {
                
            }
        }

将 <IP地址> 替换为实际的 IP 地址。

将 /path/to/cert.pem 和 /path/to/key.pem 替换为您下载的 IP 证书和私钥的实际路径。

步骤 3: 测试和重启 Nginx

使用 nginx -t 命令测试配置文件是否有语法错误。

如果没有错误，使用 sudo systemctl restart nginx 命令重启 Nginx。

常见问题解答 (FAQ)

Q: 安装了根证书，但是浏览器提示证书不受信任

A: 需要重新启动浏览器才能生效。

Q: 我需要定期更新证书吗？

A: 不需要，系统默认签发 20 年的证书。

Q: 如果有人未安装根证书，会发生什么？

A: 未安装根证书的用户可能会遇到浏览器警告，提示该站点不受信任。

Q: 可以为多个 IP 地址签发证书吗？

A: 当然可以。只需为每个 IP 地址单独申请即可。
